# CLAUDE.md — قواعد ثابتة لكل جلسة على مشروع UPAP

هذا الملف يُقرأ في بداية كل جلسة عمل (Claude Code أو أي مساعد آخر) على هذا
المستودع. لا تُخالف هذه القواعد إلا بإذن صريح ومكتوب من صاحب المشروع.

## القواعد الصارمة (Hard Rules)

1. **صفر دولار**: ممنوع أي مكتبة أو خدمة أو API يتطلب بطاقة ائتمان أو اشتراكاً مدفوعاً.
2. **يعمل من الجوال**: كل شيء يُختبر بافتراض أن المستخدم يعمل من Termux أو GitHub Codespaces أو متصفح الجوال فقط.
3. **اللغة**: التعليقات داخل الكود بالعربية، أسماء المتغيرات والدوال بالإنجليزية.
4. **Modular**: كل وحدة (وكيل، مهنة، مكوّن UI) مستقلة وقابلة للفصل والتركيب من جديد.
5. **Audit Log إلزامي**: أي عملية تُغيّر بيانات أو تستدعي AI يجب أن تُسجَّل عبر `core/engine/audit.ts`. لا استثناء.
6. **العزل التام**: لا مشاركة بيانات بين عملاء مختلفين — Row Level Security مفعّل دائماً في Supabase.
7. **متعدد الدول من اليوم الأول**: أي وكيل جديد يُختبر على 3 دول مختلفة كحد أدنى (راجع `agent.test.ts`).
8. **الشفافية**: أي قرار يتخذه وكيل (تصنيف، رفض، تحذير) يجب أن يكون له تفسير نصي واضح.
9. **لا تحذف بدون إذن**: لا تحذف ملفاً أو جدول قاعدة بيانات أو بيانات عميل دون إذن صريح ومكتوب.
10. **اسأل قبل الافتراض**: إن لم تكن متأكداً من قرار معماري أو منتجي، اسأل صاحب المشروع بدل أن تفترض.

## قبل بناء أي وكيل حقيقي جديد

لا تبدأ ببناء وكيل فعلي (وليس قالباً) أو واجهة نهائية دون تأكيد صريح من صاحب
المشروع على: اسم الوكيل، المهنة، الدول المستهدفة أولاً، ومخطط JSON للمخرجات.

## ترتيب العمل المعتمد

خطوة واحدة في كل مرة → أظهر النتيجة → انتظر التأكيد → انتقل للخطوة التالية.
لا تُنفّذ عدة مراحل كبيرة دفعة واحدة بدون عرض النتائج على صاحب المشروع.

## بنية أي وكيل جديد (يُنسخ من core/factory/agentTemplate/)

```
professions/<profession>/agents/<agent-name>/
  agent.config.ts     — الإعدادات (الاسم، الدول، اللغات، الثقة المطلوبة)
  agent.prompt.ts      — البرومبت المتخصص
  agent.tools.ts        — الأدوات (OCR، تصنيف، تحقق...)
  agent.memory.ts       — تاريخ الطلبات + التصحيحات البشرية
  agent.validator.ts    — مخطط Zod + قواعد الدولة
  agent.test.ts          — 3 حالات اختبار حقيقية على الأقل
```
